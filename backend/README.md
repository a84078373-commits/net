# وحدة قياس جودة الإنترنت

## الحالة الحقيقية

هذه خدمة API وقاعدة SQLite حقيقيتان، مع حسابات وجلسات ونقل ثنائي وتحقق وتخزين وتجميع مكاني. لا تُنشأ أي قياسات أو حرارة عند بدء التشغيل. خدمة القياس **معطلة افتراضيًا**: localhost لا يقيس جودة الإنترنت. لا تصبح الوحدة معتمدة للإطلاق قبل نشر خادم عام واختبار WAN وأجهزة فعلية ومراجعة الخصوصية والأمان.

## التشغيل المحلي

من جذر المشروع:

```powershell
python -m pip install -r backend/requirements.txt
python -m uvicorn backend.app:app --host 127.0.0.1 --port 8765 --workers 1 --no-access-log
```

التطبيق يتصل افتراضيًا بـ `http://localhost:8765`؛ الاستثناء غير المشفر للتطوير على loopback فقط. الوثائق المحلية: `/docs`. `backend/data` مستثنى من Git. لا تضع بيانات الاختبارات فيه. لا يوجد seed إنتاجي.

## إعداد نشر القياس الفعلي

1. جهّز خادمًا تملكه، له سعة نقل كافية وموقع معروف واتصال جيد. انقل النطاق إلى عنوانه العام، وشغّل HTTPS بشهادة صالحة. هذا الخادم يقيس مسار النقل إليه، وليس كل الإنترنت أو القدرة الاسمية للخط.
2. ضع API خلف وكيل TLS مثل المثال `Caddyfile.example`. عطّل الضغط والتخزين المؤقت وتحويل الاستجابات وحشو/تحديد سرعة النقل على `/api/speed/*`. لا تستخدم CDN يجيب من cache. عطّل تسجيل الاستعلامات والأجسام ورموز Authorization، بما فيها سجلات الوكيل.
3. صدّر `SMARTCARE_PUBLIC_ORIGIN=https://نطاقك` و`SMARTCARE_SPEED_ENABLED=1` و`SMARTCARE_CORS=https://نطاقك` و`SMARTCARE_DB` لمسار دائم محمي. ملف `.env.example` إرشادي؛ التطبيق لا يحمّله تلقائيًا.
4. شغّل Uvicorn على loopback بعامل واحد. محدد المعدل وجلسات النقل في الذاكرة؛ التوسع متعدد العمال يتطلب Redis أو مخزنًا موزعًا ومعالجة معاملات للمطالبة بجلسة الاختبار. لا تفتح المنفذ الداخلي للعامة.
5. ابن Flutter:

```sh
flutter build web --dart-define=SMARTCARE_API_URL=https://your-domain.example
```

يجب أن يطابق أصل API قيمة `server_id` العامة. يرفض Flutter إجراء اختبار إنترنت على localhost حتى لو فُعّل الخادم بالخطأ. لا تعطل التحقق من TLS. للأجهزة استخدم عنوان HTTPS قابلًا للوصول، لا localhost الخاص بالهاتف.

## بروتوكول القياس وحدوده

- جلسة نقل مرتبطة بالمستخدم، 4 اختبارات/ساعة. 8 طلبات HTTP للاستجابة، يستبعد أولها ويحسب وسيط السبعة الباقية.
- تنزيل ورفع: مساران متوازيان، كتلة 2 MiB، هدف زمني 6 ثوانٍ لكل اتجاه، حد 32 MiB لكل اتجاه و64 MiB إجمالًا (حوالي 67 MB، عدا ترويسات TLS/HTTP). قد تنقل البيانات أقل من ذلك. مهلة التطبيق 40 ثانية، ومهلة جلسة النقل 45 ثانية.
- `Mbps = bytes × 8 / elapsed_seconds / 1,000,000`. يشمل التوقيت زمن بروتوكول HTTP والطريق إلى الخادم؛ ليس اختبار سعة خط معتمدًا أو ICMP ping. السرعات العليا قد تبلغ حد البيانات قبل 1.5 ثانية؛ النتيجة عندئذ **غير حاسمة ولا تُنشر**، بدل زيادة استهلاك الباقة خفية.
- الحد الأدنى للقبول 4 MiB و1.5 ثانية لكل اتجاه. الخادم يطابق حجم النقل المسجل، وعدد طلبات الاستجابة، ومعدل النقل مع المدة، وعمر الجلسة، ووقت القياس، ويرفض الجلسة المكررة أو القيم غير المنطقية.
- الأحجام المسجلة لا تكفي لإثبات صدق كل توقيت عميل خبيث. هذا تحقق اتساق وليس تصديقًا عتاديًا للقياس. يلزم تقييم مقاومة التلاعب ومراقبة الشذوذ قبل النشر الواسع.
- Jitter وفقد الحزم غير مقاسين؛ يخزنان NULL. زمن استجابة HTTP ليس فقد حزم. شركة الاتصالات NULL دائمًا حتى ربط مصدر موثوق. Wi-Fi/خلوي/سلكي من واجهة نظام التشغيل عند توفرها؛ الويب وVPN والواجهات المتعددة «غير معروف». لا نفترض 4G/5G أو شركة من الموقع.
- الاختبار بطلب صريح فقط، مع موافقة على الاستهلاك. مشاركة الموقع اختيارية، والحفظ يتطلب زرًا مستقلًا. لا حفظ للخلفية أو تكرار تلقائي للاختبار.

## قاعدة البيانات والخصوصية

`users`, `auth_sessions`, `network_measurements` تُنشأ آليًا، مع فهارس للوقت والخلية. كلمات المرور PBKDF2-HMAC-SHA256 مع salt عشوائي و600,000 تكرار. الجلسات رموز عشوائية 8 ساعات، المخزن يحتفظ ببصمتها فقط، وFlutter يحتفظ بالرمز في الذاكرة دون القرص. أرقام الجوال **غير متحققة برسائل SMS**؛ الحساب مستقل عن STC. لم يضف النظام استعادة كلمة مرور أو دخولًا إداريًا إنتاجيًا.

إذن الموقع يُطلب عند فعل صريح فقط. يقرب Flutter الموقع إلى مركز خلية 0.01 درجة قبل النقل، ويعيد الخادم تقريبه. لا يوجد عمود GPS أو إحداثيات منزل دقيقة؛ الجدول يحتفظ فقط بفهرسي الخلية، والدقة مقربة لأعلى 100 متر. نحو 1.11 كم شمال/جنوب وأقل شرق/غرب في حائل، وليس تقسيم H3 أو حدود حي رسمية.

النطاق الأولي مستطيل تغطية هندسي في `quality.json`، وليس حد حائل الإداري. لا نسند أسماء أحياء غير موثقة للخلايا. التوسع يغير نطاق الخدمة مع سياسة جغرافية معتمدة.

النشر العام يشترط 5 قياسات على الأقل و3 **حسابات** مختلفة. لا تُرجع API وجود الخلية أو عددها إذا كانت دون 3 حسابات. مع 3 حسابات لكن عينة أصغر من 5 ترجع الخلية رمادية دون مؤشرات أو أعداد دقيقة. تعدد الحسابات ليس إثبات تعدد أشخاص: تفعيل الهوية/التحقق ومقاومة Sybil، ودراسة مخاطر التفريق بين الاستعلامات المتداخلة، مطلوبان قبل جمع مواقع عامة واسعة. هذه الضوابط ليست ضمان إخفاء هوية رياضيًا.

لكل حساب مساهمة منشورة واحدة/خلية/ساعة. القياسات الخاصة دون موقع لا تدخل الخريطة. API العام لا يعرض صفوفًا فردية أو هويات. سجل المستخدم محمي، بترقيم نتائج 30 افتراضيًا و100 كحد أقصى. `DELETE /api/network-tests/mine` يحذف القياسات؛ `DELETE /api/auth/account` يحذف الحساب وقياساته وجلساته. يجب استثناء أجسام الطلبات وحدود العرض من السجلات والنسخ الاحتياطية العامة.

الاحتفاظ 90 يومًا، والحذف التلقائي عند طلبات الحفظ/الخريطة/السجل. يعمل عامل تنظيف كل 6 ساعات ما دام الخادم يعمل، مع تنظيف عند بدء التشغيل. طبّق السياسة على النسخ الاحتياطية أيضًا.

## التجميع والتصنيف والفلاتر

التجميع يتم على الخادم فقط. لا تُرسل القياسات الخام للهاتف. نقرأ حدًا أقصى 50,000 قياس/استعلام ثم نعيد الخلايا المجمعة؛ عند التجاوز نطلب تضييق النطاق. طبقة Flutter تستخدم مضلعات خلايا جغرافية صحيحة، لا بقع تُستنتج بين نقاط بلا دليل.

لكل خلية: العدد، المتوسط والوسيط للتنزيل والرفع والاستجابة، أحدث وقت وعمر البيانات. 72 ساعة تعني بيانات قديمة (رمادي). «كفاية العينة» لا تعني ثقة إحصائية أو ضمان تغطية. التصنيف يعتمد وسيط **المؤشر المختار** فقط؛ لا نخلط كثافة العينة بالجودة ولا نصنع مؤشرًا إجماليًا غير موثق.

قواعد المشروع الإرشادية في `quality.json` (ليست معيار STC رسميًا):

| المؤشر | ضعيفة جدًا | ضعيفة | متوسطة | جيدة |
|---|---|---|---|---|
| تنزيل Mbps | أقل من 5 | 5 إلى أقل من 15 | 15 إلى أقل من 50 | 50 فأكثر |
| رفع Mbps | أقل من 1 | 1 إلى أقل من 3 | 3 إلى أقل من 10 | 10 فأكثر |
| استجابة HTTP ms | أكثر من 200 | أكثر من 100 إلى 200 | أكثر من 50 إلى 100 | حتى 50 |

الألوان والحدود والحد الأدنى والاحتفاظ قابلة للضبط في الملف؛ أعد تشغيل الخدمة بعد التعديل. حافظ على حد خصوصية 3 حسابات على الأقل وحد العينات 5 أو أعلى. دقة شبكة الموقع ثابتة 0.01 درجة في طرفي النظام؛ تغييرها يتطلب ترحيلًا وتغيير تقريب العميل أيضًا، فلا تغيرها كإعداد تجميلي.

الفلاتر: وقت UTC حتى 90 يومًا، 24 ساعة/7/30 يومًا أو فترة مخصصة، حدود عرض، اتصال، تنزيل أدنى، استجابة قصوى، المؤشر، حد عينات. كل فلتر يعيد الاستعلام والتجميع والوسيط وتصنيف الكفاية. شركة الاتصالات فلتر غير متاح ويُرفض تمرير قيمة مخمّنة. التحديث يدوي وبعد حفظ قياس وعند استقرار تحريك الخريطة 650ms؛ لا يوجد polling مستمر أو اختبار خلفية.

## API

| المسار | الوصول |
|---|---|
| GET `/api/network-config` | عام: الضوابط وتوفر الاختبار |
| POST `/api/auth/register`, `/api/auth/login` | إنشاء حساب/جلسة بكلمة مرور |
| DELETE `/api/auth/session`, `/api/auth/account` | جلسة صاحب الحساب |
| POST `/api/speed/sessions` | حساب مصادق، وخادم عام مفعّل |
| GET `/api/speed/ping`, `/api/speed/download` | Bearer + X-Test-Session |
| POST `/api/speed/upload` | Bearer + X-Test-Session |
| POST `/api/network-tests` | حساب ونتيجة جلسة متسقة |
| GET/DELETE `/api/network-tests/mine` | صاحب القياسات فقط |
| GET `/api/network-heatmap` | خلايا عامة بعد قمع العينات الحساسة |
| GET `/api/network-areas/{id}` | ملخص خلية وفق الفلاتر نفسها |
| GET `/api/network-statistics` | مجاميع خلايا منشورة فقط |

## الاختبارات وما لم يُختبر

```sh
python -m pytest backend/test_api.py -q
flutter test
flutter analyze
flutter build web
```

بيانات الاختبارات لا تدخل قاعدة الإنتاج: pytest يستخدم ملفات مؤقتة مع `Settings(testing=True)`. هذا الخيار لا يقرأ من متغيرات البيئة ولا يفعّل القياس في التطبيق الإنتاجي. بيانات زمن الاختبار/الفلاتر اصطناعية **داخل fixture** فقط؛ نقل البايتات عبر الاختبار لا يدّعي WAN فعليًا.

تغطي الاختبارات الحجم الفعلي للبايتات والتطابق قبل الحفظ، الرفض، الإحداثيات، المجاميع والوسيط، العينات الصغيرة، حماية الهوية، الفترات والفلاتر، تغير الخريطة، الحذف والاحتفاظ، الإلغاء والانقطاع ورفض إذن الموقع، وحالة غياب الخدمة. اختبار الحمل الصغير 2,000 صف لا يثبت سعة تشغيل مدينة كاملة.

**بوابات القبول المتبقية:** اختبار WAN حقيقي على HTTPS مملوك، أجهزة Android وiOS فعلية داخل حائل وخارجها، مقارنة نتائج بأداة مرجعية على عدة سرعات، قياس استهلاك البيانات والبطارية، اختبار حمل موزع ومراجعة أمان واعتماد سياسة الاحتفاظ وصلاحيات الوصول ونسخ القاعدة. لا يوجد هنا اختبار ميداني أو اعتماد إطلاق ناجح.

## المصادر الخارجية

- [flutter_map](https://pub.dev/packages/flutter_map): خريطة Flutter الحالية، دون تغيير المزود أو الحاجة إلى مفتاح جديد.
- [سياسة بلاطات OpenStreetMap](https://operations.osmfoundation.org/policies/tiles/): نسب المصدر ظاهر، لا تنزيل جماعي أو prefetch. الخدمة العامة بلا SLA؛ اختر مزودًا مناسبًا وحجم استخدام مصرحًا به قبل الإطلاق، واضبط `SMARTCARE_TILE_URL` مع نسب المصدر الملائم.
- [Geolocator](https://pub.dev/packages/geolocator): إذن الموقع وHTTPS للويب؛ Android يستخدم coarse فقط، دون إذن خلفية. iOS يحتاج إعداد `BYPASS_PERMISSION_LOCATION_ALWAYS=1` في Xcode وفق الوثائق إن استُخدم CocoaPods. هذه الإعدادات لم تُختبر على جهاز iOS هنا.
- [connectivity_plus](https://pub.dev/packages/connectivity_plus): نوع واجهة الاتصال لا يثبت الوصول للإنترنت أو المشغل. ثُبّت 7.3.1 لتوافق dbus مع geolocator 14.1.1.
- [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html): مرجع معامل PBKDF2. اختيار هذه الآلية لا يمثل مراجعة أمان أو امتثالًا كاملًا.

التكاليف: نقل كل اختبار حتى 64 MiB، وخادم وقاعدة وTLS ومزود خرائط حسب مزود الاستضافة. لا توجد خدمة speedtest خارجية تُستعمل دون ترخيص أو مفتاح من شخص آخر.


### إعدادات بناء الهاتف

رُفع Android Gradle Plugin إلى 8.12.1 ليتوافق مع connectivity_plus؛ المشروع يستخدم Gradle 8.14 وJava 17. لم يُبنَ APK أو يُختبر جهاز Android في هذه الجلسة. قالب Android ما زال يحتاج هوية تطبيق وتوقيع إصدار حقيقيين قبل المتجر.

على macOS مع Swift Package Manager، يقرأ geolocator_apple المتغير التالي أثناء حل الحزمة والبناء لتجنب طلب إذن موقع دائم غير مستخدم:

```sh
BYPASS_PERMISSION_LOCATION_ALWAYS=1 flutter build ios --dart-define=SMARTCARE_API_URL=https://your-domain.example
```

يتطلب ذلك Xcode وتوقيعًا صحيحًا ومراجعة أذونات الجهاز؛ لم تُختبر هنا. لا تضف إذن موقع في الخلفية لتجاوز متطلبات البناء.
